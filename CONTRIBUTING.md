# Contributing Guidelines

Thank you for considering contributions. To help maintain consistency and quality, please follow these guidelines:

## Reporting Issues

- **Search first:** Check existing issues for duplicates before opening a new one.
- **Provide Details:** Clearly describe the bug or feature request, including steps to reproduce (if applicable), expected versus actual behavior, and environment details.

## Pull Request Process

- **Fork & Branch:** Fork the repository and create a new branch for your changes. `git checkout -b feature/your-feature-name`
- **Keep Commits Focused**: Write clear, atomic commits that reference issue numbers if applicable (e.g., "Fixes #123").
- **Document**: Update documentation as needed.
- **Submit PR**: Open a pull request to the main repository. A maintainer will review your changes.

## Code Style & Standards

- **Consistency**: Follow the established code style of the project.
- **Review Guidelines**: Be open to feedback during code reviews. Changes may be requested before merging.
- **Small & Focused**: Aim for small, focused pull requests to make reviews easier.

## Merging Policies

- **Review Required**: All pull requests need approval from one or more maintainers.
- **No Self-Merges**: Contributors should not merge their own pull requests.
- Your contributions help improve the project. Thank you for your time and effort!
